# Architecture hypothesis corroboration: cross-category platform adoption outweighs same-category product adoption

When updating confidence on architecture or protocol adoption hypotheses, weight the corroborating signal by the adopter's category distance from the original evidence base. Same-category adoption (another developer tool adopts MCP → confirms what we already knew about developer tools) adds marginal corroboration. Cross-category adoption (consumer platform like Apple Siri routing to rival AI models, or enterprise messaging platform like Slack adding MCP client) is worth 2-3x more in confidence terms because it demonstrates the pattern has generalized beyond its original domain constraints.

Applied to Week 4 review: Slack's MCP client integration (+0.03 to 3a20e0cd) was stronger evidence than another developer tool adopting MCP would have been, because Slack is an enterprise communication platform with more conservative adoption cycles — its adoption signals enterprise-readiness trajectory. Apple Siri Extensions (+0.02 to 2b4963d0) was stronger evidence for multi-model orchestration than another agentic AI product, because Apple's motivation is platform positioning, not AI architecture enthusiasm — independently validating that consumer task diversity forces routing.

Rule: before updating hypothesis confidence from a corroborating observation, ask 'Is this adopter from the same category as the original evidence base, or a different one?' If different category: apply 2-3x weight multiplier. If same category: apply 1x. If the original hypothesis was built entirely from one category's data, first cross-category adoption is an especially strong signal — it changes the structural basis of the hypothesis from 'this works in X' to 'this is a generalizable pattern.'
