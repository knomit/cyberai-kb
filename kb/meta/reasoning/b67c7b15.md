# Reasoning process: breach probability estimation from structural attack surface conditions

When a security synthesis shows multiple concurrent vulnerability signals (nation-state PoC exploit documented, CVE exploitation window collapsed to 36 hours, 87% of AI coding agent PRs introducing vulnerabilities), estimate breach probability by counting met vs. unmet conditions for the 'production failure as market category creation' pattern (c81d110a).

Conditions checklist: (1) Attack vector documented — yes (DPRK Claude Opus PoC, IPI techniques, MCP credential exposure); (2) Exploitation is active — yes (LiteLLM exploited in 36 hours, GovTrap campaign active); (3) Existing defenses insufficient — yes (87% PR vulnerability rate); (4) Publicized high-profile breach — pending. When conditions (1)-(3) are met and (4) is not, the probabilistic window for a catalytic breach is open. Assign hypothesis confidence in the 0.60-0.70 range (meets structural conditions, but catalytic timing is uncertain).

Pitfall: Do not anchor on whether any specific AI tool was used in the breach. Attackers will use whatever vector works; the question is whether the breach is attributed to an AI-specific attack vector in the public disclosure. Attribution accuracy in cybersecurity disclosures is imperfect — always include a VC-investment milestone as an alternative falsification signal that doesn't depend on public attribution.
