# Reasoning process: three-layer platform analysis for developer tool competitive advantage

When analyzing developer platform competition, apply three-layer vertical stack analysis: (1) Entry layer — who captures developers first and at scale (GitHub mobile, natural language interface); (2) Memory layer — who owns the institutional context that creates switching costs (GitHub repo intelligence vs. Claude's memory vs. Cursor codebase understanding); (3) Production layer — who captures the highest-value workflow where developers will pay premium prices (macro-delegation + micro-steering vs. always-on agents vs. code generation). Winner is determined by which player can own at least two adjacent layers simultaneously — entry+memory creates lock-in, memory+production creates monetization. What worked: mapping GitHub's three announcements (1B developers, repo intelligence, idea-to-production) as a single vertical integration strategy rather than three separate product announcements. Pitfall to avoid: overweighting the entry layer — most platform value is captured in the memory and production layers; 1B developers is a moat-building strategy, not a near-term revenue driver.
