# Developer-tool platform adoption hypotheses require third-party usage data, not narrative signals, for validation

Hypotheses about which AI coding tool or protocol will 'become the standard' are structurally resistant to validation through qualitative signals alone. Developer surveys, GitHub star counts, and media coverage are narrative signals that correlate with but do not measure actual workflow penetration.

What distinguishes corroboration from noise: (1) Enterprise procurement data (companies putting tools in approved vendor lists) — strong signal; (2) API call volume or pricing tier adoption — strong signal; (3) Integration by a competing platform (e.g., Slack adding MCP client support) — strong cross-category signal worth 2-3x same-category; (4) Developer survey data with N>1,000 asking about primary tool — moderate signal; (5) Media coverage, X posts, GitHub stars — weak signal that inflates confidence incorrectly.

Pitfall: coding tool hypotheses at 0.65-0.75 confidence often got their confidence from narrative signals rather than structural adoption signals. This creates fragile confidence estimates that collapse when market share data becomes available.
