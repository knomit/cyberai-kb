# Reasoning process: stack compression velocity as productivity multiplier indicator

When AI tools integrate across multiple layers of a production stack simultaneously (hardware inference + agentic operations + enterprise planning), the productivity multiplier is non-linear — it is the product of individual layer speedups, not the sum. Decisive evidence: Cursor always-on agents handling ops + M5 handling local inference + Pigment handling planning together remove three distinct bottlenecks simultaneously rather than sequentially. What worked: identifying which specific bottlenecks each layer removes, then treating the multipliers as multiplicative. Pitfall to avoid: anchoring on early adopter anecdotes (SF dinner, Pigment Carta case) — these are high-capability teams; median developer productivity gains will be lower and slower. Pattern applied: stack layer independence test — if each layer removes a distinct constraint without depending on the others, the speedups multiply.
