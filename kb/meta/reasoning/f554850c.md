# METHODOLOGY: Substrate-layer platform analysis as meta-layer lock-in predictor

Reasoning process: When analyzing competitive platform dynamics, identify whether any single player controls a resource layer that all competing tools require as input. If yes, that player can achieve meta-layer lock-in independent of which competing tools win — the substrate owner profits from the proliferation of competition above it.

Key signals: (1) Non-replicability of the resource (institutional memory, historical context, network effects); (2) Platform-agnostic value proposition — the substrate works regardless of which competing tool the customer chooses; (3) Structural network effects that prevent new entrants from bootstrapping the resource from scratch.

What worked: The Qualcomm/GitHub analogy made the pattern legible — both own a hardware/data substrate that all software/tooling competitors depend on. The Amazon Q outage case provided the empirical evidence that context/memory is the actual constraint, not generation quality.

Pitfalls: Substrate lock-in can be broken by disintermediation — if AI agents bypass the substrate entirely (e.g., building from natural language without ever creating traditional code artifacts), the meta-layer thesis fails. Always check for disintermediation risk.
