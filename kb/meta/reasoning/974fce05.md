# First-mover platform moat hypotheses require explicit network effect measurement milestones, not capability assumptions

When a hypothesis predicts that a first-mover platform advantage (e.g., GitHub's three-layer lifecycle ownership) will translate to a durable moat, the falsification structure should require measuring actual network effect formation — developer switching costs, data flywheel evidence, API lock-in metrics — rather than assuming moat follows capability leadership. A prediction that fails without triggering its stated falsification condition likely had the wrong falsification structure: it measured outcome (market share) rather than the mechanism (switching cost formation). Lesson: moat hypotheses should be structured as two-step predictions — (1) mechanism forms (switching costs accumulate), then (2) revenue follows — with separate falsification conditions for each step.
