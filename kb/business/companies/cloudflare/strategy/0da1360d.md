# Cloudflare is building both sides of the agent web: the means for agents to transact and the means for publishers to price or refuse them

Across 2026 Cloudflare shipped four distinct pieces of agent infrastructure that together cover both parties to an agent's web request.

FOR THE AGENT: Kitesurf, a lightweight agent-first browser running in V8 isolates on Cloudflare Workers, giving agents a browsing environment optimized for automated rather than human users. Cloudflare Wallets, giving agents stable identities and controlled access to payments for APIs, MCP tools and online content, with Virtual Wallets supporting spending limits, allow lists and transaction caps. And the Agent Access Model (AAM), an enterprise access-control model for software agents built on task-specific ephemeral credentials, which removes implicit trust in task-execution graphs and evaluates every action against the task's state; its stated principles are short-lived credentials, harness and network enforcement, minimal human oversight, evidence-based grant reviews, and unidirectional capability changes.

AGAINST THE AGENT: per-purpose AI crawler controls letting publishers separately allow or block crawlers by purpose (search indexing, AI training, or AI agents), blocking training and agent bots by default on ad-bearing pages while allowing search-only crawlers, with controls applying from September 15; a monetization tool to charge visitors — human or bot — per request; and BotBase, a public database classifying bots by behavior.

WHY THE PAIRING MATTERS: no single one of these is unusual, but the same vendor supplying agent identity and agent payment while also supplying the toggle that refuses or prices agent traffic places it on both sides of the transaction it is enabling. The position is not marginal: Cloudflare says it serves nearly 20% of the internet and that 57.5% of all HTTP requests now come from automated systems.

WHAT THIS DOES NOT MEAN: this is a characterization of a product portfolio observed across four launch announcements, not a measured claim about market power, adoption, revenue, or effectiveness. None of the four records establishes that any of these products is widely used. The Wallets controls are described as INTENDED to make agentic commerce safer, not as shown to do so; AAM is a stated model with declared principles, not an audited implementation. The 20% and 57.5% figures are Cloudflare's own reported numbers, not independently verified. And the crawler-control start date is given as September 15 in the source without a year.
