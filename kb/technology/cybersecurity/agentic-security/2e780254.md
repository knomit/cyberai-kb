# eBPF SSL Interception Eliminates MITM Certificate Requirements for LLM API Observation

Classical MITM for LLM API traffic inspection requires: iptables REDIRECT to proxy + TLS termination with substitute certificate + CA trust injection into the target process. This breaks with certificate pinning and requires process cooperation (env vars like REQUESTS_CA_BUNDLE, NODE_EXTRA_CA_CERTS).

**eBPF uprobes on SSL functions are strictly better for non-cooperative processes:**
Attach uprobes to SSL_write (captures plaintext before encryption) and SSL_read (captures plaintext after decryption) inside the process's TLS library. You intercept in process memory, not in the network path. No certificate involved. No process cooperation. No iptables rules.

**What you capture:**
- Full HTTP request body going to api.anthropic.com/v1/messages (including tool schemas)
- Full HTTP response body (including tool_use blocks with tool name and arguments)
- PID-tagged, timestamp-tagged, joinable with execution stream

**Works for:**
- Python agents (OpenSSL via ssl module)
- Node.js / Claude Code (BoringSSL — symbols stable and well-known)
- Any compiled binary using OpenSSL/BoringSSL/NSS/GnuTLS
- Processes with certificate pinning (you're below the validation layer)
- Processes you don't control and cannot configure

**Tools:** bcc sslsniff.py is the canonical reference implementation. Pixie and Cilium Hubble use this pattern for Kubernetes TLS observability.

**Requirement:** CAP_SYS_PTRACE or root to load uprobes — standard for any security agent in managed deployment.
