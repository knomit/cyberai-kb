# PID + DNS Interception as Correlation Bridge Between Intent and Execution Streams

Joining the intent and execution event streams requires a common identifier and a semantic bridge.

**PID as correlation key:** Available in both streams. LLM gateway (if local) resolves connecting process PID via SO_PEERCRED (Unix socket) or /proc/net/tcp (TCP) — no process cooperation needed. eBPF tags every event with PID.

**DNS as semantic bridge:** Intent stream contains domain names ('foobar.com' in tool args). Execution stream contains raw IPs (104.21.x.x in connect()). eBPF captures DNS queries with PID: {pid: 1234, query: 'foobar.com', resolved: '104.21.x.x'}. Domain in tool argument → DNS query → IP in connect() — semantic chain closed.

**Subprocess chaining:** Agents that execute tools via subprocesses spawn child processes with different PIDs. eBPF captures execve() with parent and child PID. Child network activity chains back via: parent_pid → execve → child_pid → child connect().

**Example joined event:**
Gateway T+0ms: pid=1234, tool=web_search, url='foobar.com'
eBPF DNS T+60ms: pid=1234, query='foobar.com' → 104.21.x.x
eBPF net T+80ms: pid=1234, connect(104.21.x.x:443)
Result: confirmed semantic match, 80ms intent-to-execution latency.
