# Constraint-Based Security as the Correct Architecture for AI Agents

Because behavioral monitoring is infeasible, the correct security model for AI agents is constraint-based: define what the agent is *allowed to do* and enforce it as a hard boundary.

**Four concrete enforcement mechanisms:**

1. **Per-tool-call argument inspection (agentic firewall):** Before any tool executes, a policy engine inspects the *arguments* of that specific call. `email.send(to='@company.com')` passes. `email.send(to='@gmail.com')` triggers review. `file.delete(path='/etc/')` blocked unconditionally. Rules written against argument patterns, not behavioral sequences.

2. **Resource class gating with declared task scope:** Task initiation declares which resource classes will be accessed. Any attempt to access an undeclared class is blocked regardless of agent intent.

3. **Irreversibility escalation:** Reads are free. Writes are logged. Destructive or externalizing operations (send email, delete file, call external API with data) require human approval or elevated confidence threshold.

4. **Rate/volume caps:** Cap emails sent, URLs fetched, documents read per task — regardless of sequence. Blunt but caps blast radius without requiring a baseline.

**Why this maps to enterprise buyers:** Reframes agent security as access control policy — which security teams already understand, have governance processes for, and have audit requirements around. The shift: from 'behavioral anomaly detection' to 'agentic firewall.'
