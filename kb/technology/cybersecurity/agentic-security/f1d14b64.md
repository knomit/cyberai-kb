# Unified eBPF Architecture for Agent Intent + Execution Observability

Both the intent stream and the execution stream can be collected entirely via eBPF, with no LLM API gateway, no MITM proxy, no process cooperation, and no framework-specific instrumentation.

**Intent stream — SSL uprobes:**
uprobe on SSL_write + SSL_read captures LLM API request/response plaintext including tool_use blocks. Works for any process regardless of how it was launched or configured.

**Execution stream — kernel kprobes:**
- connect() / sendmsg() → outbound network connections with PID, dest IP:port
- DNS (UDP port 53 or getaddrinfo()) → domain resolution with PID
- execve() → subprocess spawning with parent PID, child PID, command and args
- openat() / write() → filesystem operations (optional, for broader coverage)

**Properties of this architecture:**
- Framework-agnostic: works for LangGraph, CrewAI, AutoGen, Claude Code, compiled binaries, anything
- No gateway deployment, no iptables rules, no certificate injection
- Works for tools that don't expose configuration hooks
- Works for subprocesses spawned by agents
- Single privilege requirement: CAP_SYS_PTRACE or root for the eBPF collector
- All events PID-tagged → joinable via PID + temporal proximity + DNS bridge

**Security framing:** Treats each agent process as a security principal whose effects on infrastructure are observable and (with policy enforcement added) controllable — regardless of which internal code object within the process triggered the action.
