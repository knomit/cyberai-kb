# IPI Root Cause: No Provenance Boundary Exists in LLM Context Assembly

Indirect Prompt Injection is a structural consequence of how transformer LLMs work, not a bug in any specific implementation.

**Mechanism:** Every LLM call is stateless. The application reconstructs full context as one concatenated text block: system prompt + conversation history + retrieved external content. No architectural enforcement boundary exists between 'instructions to follow' and 'data to process.'

**Why injected instructions compete effectively:**
1. Recency bias — transformer attention weights later tokens more heavily
2. Authority framing — 'SYSTEM:' or 'IGNORE PREVIOUS INSTRUCTIONS' exploits fine-tuning patterns
3. No provenance signal — model cannot distinguish developer-typed text from email content from tool output

**Why model-level fixes are limited:** 'Distinguish instructions from data' is semantically equivalent to 'understand natural language in context' — the same capability that makes the model useful and susceptible. Content classifiers can be evaded by encoding or framing. The correct defense layer is context assembly (application layer), not the model.
