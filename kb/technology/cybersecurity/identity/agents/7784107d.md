# A2A Protocol and the Agent-to-Agent Authentication Gap in Popular Frameworks

**Current reality in popular frameworks:**
LangGraph, CrewAI, AutoGen, and OpenAI Agents SDK share credentials via environment variables across all agents in a process. No per-agent identity. Compromising one agent compromises all. When Agent A delegates to Agent B, no identity verification occurs — Agent B cannot verify the caller or whether Agent A was compromised (Confused Deputy problem at machine speed).

**Google's A2A Protocol (60+ company backing):**
Each agent publishes an Agent Card (JSON at /.well-known/agent.json) declaring capabilities and required auth schemes. Flow: caller reads Agent Card → obtains credentials via OAuth2 → calls made with Authorization: Bearer JWT. Schemes: apiKey, http Bearer, oauth2, openIdConnect, mtls. Auth0 and PingIdentity have production integrations.

**The gap:**
A2A provides the protocol but not adoption. LangGraph, CrewAI, AutoGen don't ship A2A natively. Locally-running and homegrown agents never will. No vendor ships mutual agent-to-agent auth as a production-ready framework-integrated feature. Product gap: a runtime enforcement layer that automatically issues scoped short-lived tokens per delegation, validates on receipt, and revokes on task completion.
