# Claude Opus 5 produced an ASLR-defeating exploit in hours where Opus 4.8 failed across multiple sessions

Hacktron researchers reported a sharp capability discontinuity between consecutive Anthropic model releases on the same offensive-security task. Claude Opus 4.8 struggled across several sessions to build a working exploit for the libheif memory bugs once ASLR (address space layout randomization) was enabled. Claude Opus 5, released on the evening of 2026-07-24, produced a working exploit within hours in a fresh session; the researchers used leaked adjacent memory from the out-of-bounds read to defeat ASLR and turn a crash into code execution. Two qualifications are part of the finding and must not be dropped: (1) Opus 5 shipped with safeguards intended to prevent it writing exploit code against real targets, and the researchers circumvented them by pointing the model at their own test server disguised as a capture-the-flag practice target and running it in an automated loop; and (2) the researchers state the work was NOT hands-off — skilled human direction still mattered, and this was not automated hacking with no one at the controls. Across the wider 'HEIF Heist' campaign, Hacktron says it found the same class of image-decoding flaws in software used by other large companies over roughly two months at a total cost of under $3,000 in AI usage, linking it to reported bugs in Slack, Meta products, GitHub Enterprise, and Next.js — though The Hacker News notes these broader claims are backed unevenly, with the Next.js flaw confirmed in Vercel's own advisory. This does NOT mean a frontier model autonomously hacks targets on request; it means the model collapsed the time and skill required for a step that had been the human bottleneck, under human direction and after a safeguard bypass.
