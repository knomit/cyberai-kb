# Tool-output prompt injection evades screens that inspect input and action separately

Armo Security argued (2026-09) that prompt injections embedded in TOOL RESULTS — rather than in user input — slip past conventional safeguards because input screening and action screening inspect different moments of the agent loop, leaving the gap between them unguarded. The proposed detection signal is a 'precedent gap': flagging when an agent suddenly issues a tool call, or uses argument values, with no precedent anywhere in its own execution history. The actionable consequence is that guarding agent inputs and guarding agent actions are not jointly sufficient; the returned-data boundary needs its own check.
