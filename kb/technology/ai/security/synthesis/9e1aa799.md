# AI Security Measurement Systematically Understates Real-World Risk Across All Layers (2026)

Three independent data points in May 2026 converge on the same structural conclusion: every layer of AI security evaluation currently in use understates actual risk by a significant margin.

**Benchmark layer (Cisco research):** Single-turn attack success rate (ASR) — the dominant benchmark metric — does not predict multi-turn vulnerability. Across 15 frontier models, multi-turn ASR ranged 7.89%–88.30% vs single-turn 2.19%–64.91%. GPT-5.4 showed a 9x increase in vulnerability. Anthropic Claude had the lowest single-turn ASR but still reached 11–16% under multi-turn pressure. Conclusion: model cards with safety benchmarks are measuring the wrong scenario.

**Deployment layer (Wiz State of AI in Cloud 2026):** 80% of organizations use AI IDE extensions; ~1 in 5 using AI coding platforms have systemic security weaknesses due to insecure AI-generated defaults. 68% of self-hosted model users ingest models via third-party software ('transitive AI'), inheriting supply chain risks without explicit deployment. 57% deploy self-hosted agents; 80% have adopted MCP servers, creating overprivileged control planes.

**Vulnerability discovery layer (Anthropic Project Glasswing):** Claude Mythos AI found 10,000+ high/critical-severity vulnerabilities across systemically important open-source software in ~one month — 1,726 confirmed true positives, 1,094 high/critical, 97 patched. These were not caught by normal security processes.

**Aggregate pattern:** AI security is materially worse than reported metrics suggest at every measurement layer — model benchmarks, deployment posture assessments, and traditional vulnerability scanning all have systematic blind spots that only become visible when the evaluation method is changed or augmented with AI.
