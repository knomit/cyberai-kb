# Across all four of Google's 2026 agent surfaces the control plane shipped with the capability, and three of the four ship budget controls — spend governance built into the runtime

EXTENDS, DOES NOT REPLACE, kb/technology/ai/agents/a44c5656.md. That fact establishes that August 2026 agents shipped into existing work surfaces rather than as standalone apps, and notes as a secondary move that 'enterprise controls arrive with the surface, not after it', citing Antigravity's sandbox, tool-permission, budget, identity and audit controls. This record adds that the pattern is uniform across Google's entire agent line, and identifies which control recurs.

FOUR SURFACES, FOUR CONTROL PLANES.
- CUSTOM AGENTS in Antigravity 2.0 and the Antigravity CLI: specialized file-based configurations defining a role with its own SCOPED instructions, tools and CONSTRAINTS, intended to keep active context clean and minimize token overhead. They complement rather than replace skills and dynamic subagents.
- ANTIGRAVITY in Gemini Enterprise and IDE extensions (VS Code, Visual Studio, JetBrains, Zed): administrators can set SANDBOX, TOOL-PERMISSION, BUDGET, IDENTITY and AUDIT controls.
- MANAGED AGENTS in the Gemini API: background asynchronous execution, remote MCP server integration, custom function calling and credential refresh across interactions, with reasoning, code execution, package installation, file management and web access confined to an ISOLATED CLOUD SANDBOX.
- MANAGED AGENTS with Gemini 3.6 Flash: ENVIRONMENT HOOKS for inspecting tool calls, BUDGET CONTROLS, scheduled triggers, model selection and free-tier access.

THE RECURRING CONTROL IS BUDGET. Three of the four ship explicit spend limits, and the fourth (Custom Agents) is justified partly on token economy — 'keep active context clean and minimize token overhead'. Sandboxing and permissions are the expected controls for an autonomous system; a budget ceiling is a different kind of control, and its presence in the runtime means the vendor treats uncontrolled SPEND as a first-class failure mode alongside uncontrolled ACTION.

WHY THAT CONNECTS OUTWARD. This corpus separately records an enterprise 'token panic' over agent inference costs, and records that the evidence for a 2026 cost-efficiency shift is assembled from non-comparable metrics with cost per successful task unpublished. Budget controls appearing inside the agent runtime are the same pressure expressed in product architecture rather than in price lists — a vendor giving buyers a hard stop because neither party can predict what a long-running agent will consume.

WHAT THIS DOES NOT MEAN:
- These are VENDOR ANNOUNCEMENTS across a single vendor. Nothing here reports adoption, whether administrators configure these controls, or whether the budget ceilings bind in practice.
- It does NOT claim Google is unusual. The canonical fact this extends records the same controls-with-surface move at other vendors; the increment here is uniformity across one vendor's line and the specific recurrence of budget.
- It does NOT establish that spend governance WORKS. A budget control caps exposure; it says nothing about cost per completed task, which remains the unpublished variable.
- The four announcements span different dates and products and are not a single coordinated release.
