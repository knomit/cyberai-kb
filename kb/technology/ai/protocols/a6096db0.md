# Google is authoring the standard at four separate seams of the agent stack — and where adoption was actually measured, the frameworks ignore it and keep the insecure default

Between March and May 2026 Google originated or co-developed a protocol at four distinct interface boundaries of the agent stack. Standard-setting at every seam is the pattern; the adoption gap is the thing that makes it worth watching rather than assuming.

THE FOUR SEAMS.
- AGENT TO AGENT: the A2A protocol, with 60+ company backing. Each agent publishes an Agent Card (JSON at /.well-known/agent.json) declaring capabilities and required auth schemes; a caller reads the card, obtains credentials via OAuth2, and calls with Authorization: Bearer JWT. Supported schemes: apiKey, http Bearer, oauth2, openIdConnect, mtls. Auth0 and PingIdentity have production integrations.
- AGENT TO UI: AG-UI, developed by CopilotKit with GOOGLE CO-DEVELOPING the A2UI declarative sub-spec, letting agents render interactive components (charts, forms, cards, canvases) instead of plain text. First-party integrations with LangGraph, Google, AWS and Microsoft. It defines three tiers — Controlled (agent triggers predefined components), Declarative/A2UI (agent assembles layouts from a catalog), Open-Ended (agent generates UI from scratch via MCP Apps).
- AGENT TO WEB: WebMCP, released by Google as an early preview in May 2026, described as 'a standard way for exposing structured tools', positioned as web-native infrastructure for agent communication with web services.
- AGENT TO DESIGN TOOL: the Stitch MCP server and SDK, enabling integration into other design and coding tools, alongside DESIGN.md as an exportable/importable cross-tool rules format.

AUTHORSHIP IS NOT ADOPTION, AND THIS IS MEASURED FOR A2A ONLY. Despite 60+ backers, A2A ships natively in none of the frameworks that matter. LangGraph, CrewAI, AutoGen and the OpenAI Agents SDK all share credentials via ENVIRONMENT VARIABLES across every agent in a process. There is no per-agent identity: compromising one agent compromises all of them, and when Agent A delegates to Agent B, no identity verification occurs — B cannot verify the caller, or whether A was already compromised. That is the Confused Deputy problem at machine speed. Locally-running and homegrown agents never will adopt it. The named product gap is a runtime enforcement layer that issues scoped short-lived tokens per delegation, validates on receipt, and revokes on task completion — which no vendor ships as a production-ready framework-integrated feature.

WHAT THIS DOES NOT MEAN:
- The adoption gap is documented for A2A ONLY. Nothing here measures uptake of AG-UI, WebMCP or the Stitch MCP server, and their adoption must NOT be assumed to be similarly weak — or similarly strong.
- 'Google authors the seam' does NOT mean Google controls it. AG-UI is CopilotKit's protocol with Google co-developing one sub-spec; MCP itself is not Google's. WebMCP is an EARLY PREVIEW, not a shipped standard.
- It does NOT claim the four efforts are coordinated. They come from different teams and different months; the common author is the observation, not a stated strategy.
- A2A's 60+ backers and the Auth0/PingIdentity integrations are real; 'no adoption' refers specifically to the four named agent FRAMEWORKS, not to the ecosystem generally.
