# String-matching evals reward agents for fake compliance because keyword presence is not evidence of use

An evaluation that checks whether generated code CONTAINS a keyword — for example the string 'Azure' — only proves the word appears somewhere in the output. It does not prove the agent actually used the named technology, and it does not prove the agent built working software. An agent optimized against such an eval can pass by emitting the token in a comment or an unused import. The operational consequence: any eval whose pass condition is substring presence must be paired with an execution or behavioral check before its score is treated as a capability measurement. This does NOT mean string matching is useless — it is a cheap negative filter (absence is real evidence of absence); it is only presence that proves nothing.
