# Plugin4Shell: four AI coding agents install pinned plugins without verifying the commit hash

Air Security disclosed on 18 September 2026 that Claude Code, OpenAI Codex, GitHub Copilot and Google Gemini CLI fetch plugins pinned to a specific reviewed commit hash but never verify that the code they receive actually matches that hash. On a git host that permits branch names shaped like commit hashes, a plugin repository owner can point such a branch at different code; the agent installs the substituted code while still reporting the locked version. Because a plugin runs with the same access as the person using the agent, swapped code reaches that user's files, saved credentials, and logged-in systems. Critically, the attack requires ALL of: a git host that allows hash-shaped branch names (Bitbucket or a self-hosted git server, NOT GitHub, which forbids such names), and a plugin installed from that host. Gemini CLI is attacked differently — via a repository whose main branch is named FETCH_HEAD, which GitHub's rule may not block. Background auto-update, on by default in Claude Code and Codex only for their own GitHub-hosted marketplaces, would remove the need for victim action where it applies. Status: Anthropic fixed in Claude Code 2.1.179, OpenAI in Codex 0.146.0, GitHub Copilot unpatched, Google will not patch Gemini CLI (being retired in favor of Antigravity). As of 18 September 2026 no CVE was assigned, no vendor advisory published, and no real-world exploitation observed. Operational consequence: the fix must ship in the agent, not the marketplace, because each agent checks the lock on the user's own machine. This does NOT mean every plugin install is exposed — installing only from the agents' default GitHub-based marketplaces avoids the branch-name variant.
