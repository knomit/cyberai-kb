# Mid-2026 attack wave: abusing trusted platforms, registries, and AI-dev tooling instead of perimeter flaws

A cluster of June 2026 incidents shows attackers converging on abuse of trusted infrastructure and reputation rather than classic perimeter exploits. Examples: 145 @mastra/* npm packages poisoned via a hijacked contributor account injecting an 'easy-day-js' cryptominer dependency; the Miasma/TeamPCP worm planting persistence hooks directly in AI coding-agent configs (Claude Code, Gemini CLI, Cursor, VS Code) so a credential harvester runs on every session and survives token rotation; a crypto-clipper campaign manufacturing a 'fake reputation economy' across news sites, GitHub/SourceForge, YouTube, and coordinated VirusTotal comments; DragonForce ransomware hiding C2 traffic inside legitimate Microsoft Teams TURN relays; and a Google Vertex AI SDK 'bucket squatting' flaw exploitable with only a victim's public project ID. The common thread: the trust developers and defenders place in package registries, cloud SDKs, AI dev tools, reputation signals, and SaaS network traffic is itself the attack surface. GitHub's planned move to disable npm install scripts by default in npm v12 is a defensive response to the same registry-trust problem.
