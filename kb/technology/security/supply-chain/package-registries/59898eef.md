# 2026 package-registry attacks: automated mass-publishing and post-install/dependency triggers, multiple distinct actors

Across mid-2026, package-registry supply-chain attacks share a recurring playbook even when run by different actors: rapid automated mass-publishing of many package versions, and execution triggered at install time via post-install hooks or injected dependencies. Instances include the TeamPCP/Miasma multi-registry campaign (IronWorm on npm, Hades on PyPI, plus direct GitHub repo compromise and AI-coding-agent config injection), the recurring npm/PyPI post-install-hook stealers catalogued in THN recaps (turbo-axios/faster-axios → Epsilon Stealer, cms-store-ren, PyPI 'parsimonius'), and the separately-attributed Mastra '@mastra/*' compromise where account 'ehindero' mass-published 140+ packages in 88 minutes that pull an 'easy-day-js' (dayjs clone) cryptominer dependency. The Mastra attack uses dependency injection rather than a TeamPCP-style worm and should not be attributed to TeamPCP without evidence, but it fits the same structural pattern of registry trust + automated publishing + install-time execution. This is the attack-side counterpart to GitHub's defensive move to disable npm install scripts by default in npm v12.
