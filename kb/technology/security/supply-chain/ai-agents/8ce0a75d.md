# Miasma worm persists via AI coding agent config injection — a .claude/settings.json SessionStart hook runs a credential harvester on every session, and Microsoft disabled 73 GitHub repositories in response

MERGED from the detailed Miasma config-injection record and a thinner record of the same Microsoft repository takedown (which reported it as 'more than 70' repositories and carried zero recorded sources). The thinner record's framing claim is preserved below.

The Miasma worm (TeamPCP campaign, June 2026) introduced a NOVEL PERSISTENCE MECHANISM targeting AI coding agent configuration files. When it compromises a GitHub repository DIRECTLY (skipping package registries entirely), it plants hooks in FIVE developer tool configs simultaneously: Claude Code (.claude/settings.json), Gemini CLI, Cursor, VS Code, and npm test scripts.

THE CLAUDE CODE VECTOR IS THE MOST PERSISTENT: Miasma embeds an Anthropic Claude Code SessionStart hook in .claude/settings.json that executes a 4.3 MB credential-harvesting payload runner AUTOMATICALLY ON EVERY CLAUDE CODE SESSION OPEN. Critically, THIS PERSISTENCE SURVIVES TOKEN ROTATIONS — the hook re-harvests credentials on each subsequent session, meaning ROTATING A COMPROMISED TOKEN DOES NOT STOP EXFILTRATION.

PAYLOAD ARCHITECTURE: four-layer obfuscation stack, Bun-as-runtime, AES-GCM payload staging through /tmp, bypass_2fa: true worm propagation, runner memory extraction via /proc/mem.

THE STRUCTURAL SHIFT: from SUPPLY CHAIN attacks (poison the package, wait for install) to DEVELOPER ENVIRONMENT attacks (poison the repo, trigger on every AI coding session). A developer who clones or opens a compromised repository in Claude Code will silently execute the harvester — NO INSTALL STEP REQUIRED.

SCOPE: 73 Microsoft GitHub repositories disabled across two automated waves (105 seconds) in early June 2026 — reported as 'more than 70' in one account and 73 in another; Red Hat Cloud Services npm namespace compromised (32 packages, 116,991 combined weekly downloads). ZERO CVEs ASSIGNED across the entire campaign as of June 2026.

FRAMING CLAIM CARRIED FROM THE MERGED RECORD: the Microsoft repository takedown represents ONE OF THE FIRST LARGE-SCALE CORPORATE REMEDIATION ACTIONS EXPLICITLY ATTRIBUTED TO AN AI-AGENT SUPPLY-CHAIN COMPROMISE. It is consistent with, and downstream of, the same Miasma/TeamPCP campaign that previously exfiltrated data from 3,800+ internal Microsoft GitHub repositories (confirmed 2026-05-20) — see kb/technology/cybersecurity/threats/supply-chain/4bd87b26.md.

WHAT THIS DOES NOT MEAN: the 'one of the first' framing came from a record with ZERO recorded sources and is a characterization, not a verified precedence claim. The 70-versus-73 repository count discrepancy is preserved rather than resolved. Nothing here establishes how many developers actually opened a poisoned repository in an agent session.
