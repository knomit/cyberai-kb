# Shai-Hulud worm resurfaced in four npm packages 111 days later with a hash-identical, already-indexed payload

Aikido Security found four npm packages — feishu-docx-mcp@0.3.2, bmc-i18n-extract-cli@1.1.1, blueai-cli@0.7.0, and bmc-translate-utils@1.1.1 — containing the Shai-Hulud worm previously seen in the May 2026 AntV attack, after a 111-day gap.

Aikido's point is not the package count but the detection gap: 'a payload with a known, published, indexed hash sat untouched in nobody's toolchain for over three months and was then republished on a registry that, as of this year, explicitly scans every package before it goes live... That gap between what registry-level scanning claims to do and what a hash-identical reactivation shows it actually caught is the real story here.'

Operational consequence: do not treat 'the registry scans every package' as coverage against known-bad payloads. The compound failure required BOTH that the hash was already published and indexed AND that the registry's pre-publication scan ran — and it still shipped.
