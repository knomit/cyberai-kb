# GhostSplice: ASSET Group showed a malicious MCP server can exfiltrate secrets by splitting one instruction across tool description, tool result and sampling message

GhostSplice is an attack technique against AI coding assistants in which a malicious request is FRAGMENTED ACROSS SEPARATE CHANNELS — an MCP tool description, a tool result, and a server-initiated sampling message — each benign in isolation. The assistant stitches the fragments back into one instruction.

WHY IT WORKS. ASSET Research Group describes this as CROSS-CHANNEL TRUST FRAGMENTATION: all tool channels, files and user chat pour into a single undifferentiated block of assistant memory with no marking of provenance, so the attacker never needs any individual piece of content to look dangerous. Note the precise scope of the mechanism — although MCP does preserve structured tool/result boundaries at the protocol level, agents can still combine instructions across those boundaries within the same working context. The failure is in how the agent consumes the channels, not in MCP's lack of structure.

WHAT IT ACHIEVES. ASSET demonstrated that a malicious tool server connected to an AI coding assistant over the Model Context Protocol can exfiltrate SSH keys, environment secrets, source code, and customer data without sending any single obviously harmful instruction. The technique can succeed EVEN AFTER a blunt version of the same request is refused — the refusal of the direct ask is not evidence the assistant is protected against the fragmented one.

Merged from two records of the same ASSET Research Group work: one naming and characterizing the GhostSplice technique and the trust-fragmentation mechanism, the other recording the demonstrated exfiltration targets, the MCP-boundaries nuance, and the post-refusal success.
