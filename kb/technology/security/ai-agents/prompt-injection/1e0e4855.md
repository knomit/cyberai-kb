# Goal hijacking works whenever an agent treats retrieved content as instructions, turning its own tools against it

Goal hijacking against an AI agent works under one condition: the agent treats RETRIEVED content as instructions. When it does, any webpage, email, or document the agent fetches can redirect the agent's connected tools toward the attacker's goal — the attacker does not need to compromise the model, the agent framework, or the tools themselves, only to place text where the agent will read it. The compound condition is what matters: retrieval alone is safe, and tool access alone is safe; the hijack requires retrieved content being interpreted as instruction WHILE the agent holds tool access. The mitigation follows from that: separate the instruction channel from the data channel, so retrieved content can never be promoted to instruction status regardless of what it says.
