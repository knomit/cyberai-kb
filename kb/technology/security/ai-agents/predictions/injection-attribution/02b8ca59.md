# Hypothesis: A named-victim enterprise breach will be publicly attributed to indirect prompt injection via an agent's trusted tool channel by Q4 2027

Prediction (forward-looking): The synthesis establishes indirect prompt injection via trusted data channels as the dominant AI-agent attack vector in 2026 — but every instance underpinning it is researcher-demonstrated, not observed in the wild. Tenet Security's 'Agentjacking' (instructions planted in Sentry error events, returned by the Sentry MCP server to Claude Code/Cursor as trusted diagnostic output, yielding arbitrary code execution) and the OpenClaw work by Imperva/Varonis are proofs of concept. I predict the vector crosses from demonstrated to exploited, with public attribution.

Settlement criterion (by 31 Dec 2027): CONFIRMED if a public disclosure — SEC 8-K, vendor or victim postmortem, CISA advisory, or major-outlet reporting with a NAMED victim organization — attributes initial access or material impact to attacker instructions injected through an agent's tool-output or data channel (MCP server response, error-tracker event, ticket body, retrieved document, CI log) that the agent treated as trusted. FALSIFIED if no such named-victim attribution exists by that date.

Deliberate exclusions from the settlement criterion: (a) researcher PoCs, bug bounties, and red-team exercises do not count — the whole point is the demonstrated/exploited gap; (b) attacks where a human was phished and the agent was merely the payload delivery path do not count — the injection must enter via a channel the agent trusts programmatically; (c) malicious-package supply-chain compromise does not count — that is a distinct vector already covered by the SolarWinds-scale hypothesis (kb/technology/cybersecurity/threats/supply-chain/7cc50183.md), and conflating the two would let either one settle this.

Reasoning: the preconditions are unusually complete. The vector is documented and public, the tooling (MCP servers wired into coding agents with file and terminal access) is in broad production use, and the corroborating synthesis notes that an agent's access IS the attacker's blast radius — so a successful injection inherits real permissions rather than needing separate escalation. DigiCert's survey finding ~50% of enterprises suffering incidents from unauthorized or misconfigured agents suggests exploitation may already be occurring below the attribution threshold.

## 2026-08-17 UPDATE — confidence 0.60 → 0.56

A new technique, **GhostSplice** (ASSET Group, successor to GhostCommit), was disclosed: a malicious request is fragmented across three separate MCP channels — a tool description, a tool result, and a sampling message — each fragment benign in isolation. Because all tool channels, files and user chat pour into one undifferentiated block of assistant memory with no marking of provenance, the assistant reassembles the fragments into a single instruction. ASSET Group calls this cross-channel trust fragmentation: the attacker never needs any individual piece of content to look dangerous.

**Settlement impact: none.** GhostSplice is researcher-demonstrated and therefore excluded by criterion (a). It does not move the hypothesis toward confirmation.

**Why this is nonetheless a small NEGATIVE update.** Roughly a month has passed and the demonstrated column gained another sophisticated entry while the exploited-and-attributed column stayed at zero. Each additional demonstration without a corresponding in-the-wild attribution is weak evidence for the un-attributability branch the hypothesis already flagged as its central risk — that exploitation is occurring but forensics cannot reconstruct agent decision provenance. GhostSplice sharpens this specifically: an attack whose defining property is that no single input looks malicious is, by construction, one that post-hoc log review is least likely to reconstruct. If the technique that is hardest to attribute is also the direction research is moving, the probability that a NAMED-victim attribution materialises by Q4 2027 falls somewhat, even as the probability that such attacks OCCUR rises.

**Why only −0.04.** The window runs to 31 Dec 2027; sixteen months remain and one month of no-attribution is close to uninformative on its own. The decrement reflects the direction of the research frontier, not the passage of time.

**Load-bearing gap — unchanged and now more acute.** The named resolving evidence was 'any agent platform shipping tamper-evident provenance logging that ties actions to the specific input that triggered them; or conversely, any DFIR vendor publishing that agent-mediated incidents are un-attributable with current telemetry.' Neither appeared. ASSET Group's diagnosis — that there exists no marking separating content by source — is an architectural statement of exactly the precondition that would make provenance logging possible, and it says the precondition is absent across current implementations. That is closer to the second (pessimistic) branch than the first, without being a DFIR publication that would settle it.

Load-bearing evidence gap: whether attribution is even possible. This is the reason for the sub-0.7 confidence and the most valuable thing to check. An injected instruction that executes through an agent's legitimate credentials leaves logs that look like authorized activity; forensics may record WHAT the agent did but not that a Sentry event body caused it. If incident responders report they cannot reconstruct agent decision provenance, this hypothesis may be UNFALSIFIABLE IN PRACTICE rather than false — exploitation could be widespread and simply never attributed. Evidence that would shift confidence: any agent platform shipping tamper-evident provenance logging that ties actions to the specific input that triggered them; or conversely, any DFIR vendor publishing that agent-mediated incidents are un-attributable with current telemetry.

WHAT THIS DOES NOT MEAN: this does not predict a breach of any particular scale, does not name a likely victim or vendor, and does not claim MCP is insecure by design — the vector is a property of agents acting on untrusted input with real permissions, not of any one protocol. Non-confirmation by the date should be read as ambiguous between 'did not happen' and 'happened but could not be attributed', per the gap above.
