# A single browser extension can hijack built-in AI assistants across five Chromium products

Forever Security researcher Gal Weizman demonstrated that one ordinary browser extension can take control of the AI assistants built into five Chromium-based products: Gemini Live in Chrome, Perplexity Comet, Microsoft Edge, Opera Neon, and the Claude in Chrome extension. Once installed, the extension reached each product's built-in AI with a single click. Capability varied by product: on Comet, Edge, Opera Neon, and Claude in Chrome it could drive the AI agent to act on the attacker's behalf; on Chrome and Comet it could read files from the user's computer; on Chrome alone it could also switch on the camera and microphone. The extension required only two common permissions — one that modifies web pages (the kind ad blockers use) and declarativeNetRequest, which modifies browser network traffic — and together these let it inject code into the trusted page and speak to the AI as if it were the vendor. Two preconditions bound the result, and both must be stated: these are researcher demonstrations NOT observed in the wild, AND each requires the attacker's extension to already be running in the victim's browser. The Chrome case was first disclosed in March as GlicJack, tracked as CVE-2026-0628, rated 8.8 by CISA (which set the score because NIST had not), and fixed by Google in early January 2026 in Chrome 143.0.7499.192. Of the four new cases only the Edge finding received a CVE — CVE-2026-55945, rated 4.2, fixed by Microsoft. Operational consequence: extension permissions that look mundane (page modification plus declarativeNetRequest) are sufficient to impersonate the vendor to an in-browser AI agent, so extension review must treat them as privileged when an AI assistant is present.
