# The exploitable surface is any connector that relays third-party-writable data to an agent as trusted output — the ingestion endpoint's openness and the connector's trust label are two halves of one flaw

MECHANISM: content that any third party can write into a system is later relayed to an agent through an integration that presents it as trusted internal output, and the agent, holding tool access, acts on it as instruction — so the attacker needs no access to the model, the agent framework, or the tools, only a write path into something the agent will read.

The general condition, and why it is compound: goal hijacking works when an agent treats RETRIEVED content as instructions. Retrieval alone is safe, and tool access alone is safe; the hijack requires retrieved content being interpreted as instruction WHILE the agent holds tool access. Any webpage, email, or document the agent fetches can then redirect its connected tools toward the attacker's goal. The mitigation follows from the condition: separate the instruction channel from the data channel, so retrieved content can never be promoted to instruction status regardless of what it says.

The structural form this takes in a real integration: the flaw sits at the INTERSECTION of two components that are each individually reasonable — an ingestion endpoint that by design accepts arbitrary payloads from anyone holding a publishing key, and a connector server that returns that same stored data to agents as trusted system output. Neither component is wrong on its own; joining them is what turns an anonymous write into agent-executed code, with the attacker's text arriving dressed as legitimate diagnostic or operational content that the agent has every reason to follow.

WHAT FOLLOWS: when auditing an agent's connectors, the question is not whether the upstream system is trustworthy but whether any third party can WRITE into the records that connector exposes. A connector over a system with an open or key-only ingestion path is an instruction channel for whoever holds that path, no matter how reputable the vendor. Trust labels applied at the connector boundary are applied to the transport, not to the provenance of the content flowing through it.

WHAT THIS DOES NOT MEAN: this does not claim all connectors or all error-tracking integrations are vulnerable, nor that the general principle was derived from the specific case — the principle stands independently, and the integration case is one instance of its precondition being met by an architecture rather than by a user fetching a hostile document.
