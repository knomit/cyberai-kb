# AI agents are compromised via over-broad permissions and injected instructions, not model breaks

A recurring 2026 pattern in agentic-AI security: attackers don't defeat the model's guardrails directly — they abuse the agent's permissions and the fact that agents act on untrusted inputs. Varonis's 'Rogue Agent' in Google Dialogflow CX let one over-permissioned Code Block agent (via dialogflow.playbooks.update) pivot to every agent in a Google Cloud project. In the OpenClaw research, Imperva hid executable instructions in shared contacts/vCards/location pins, and Varonis showed a single plain email could talk the agent into exfiltrating (mock) AWS keys and a customer export — an indirect prompt-injection weakness no patch fully fixes, only permission limits. The mitigation theme is least-privilege agent identities and constraining what agents can access and act on.
