# Pattern: AI coding agents turn 'opening a repo/workspace' into a code-execution and credential-theft attack surface

Multiple June 2026 disclosures converge on a single theme: autonomous AI coding agents collapse the gap between viewing untrusted code and executing it. The Amazon Q Developer flaw (CVE-2026-12957) showed a single attacker-supplied MCP config file (.amazonq/mcp.json) in a cloned repo was enough to spawn processes inheriting the developer's full environment (AWS keys, cloud tokens, SSH sockets), turning 'git clone' into cloud-credential compromise once the workspace was trusted. The broader 'lethal trifecta' concept frames the same risk: an agent with internet access, local identity/permissions, and sensitive-code access can read credentials, delete files, and impersonate the user. Together these argue that AI dev-tool agents are a first-class attack surface, motivating mitigations like sandboxing, scoped tool permissions, audit logging, and moving agents into remote pre-hardened environments.
