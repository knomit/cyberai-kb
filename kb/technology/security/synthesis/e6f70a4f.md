# AI is simultaneously attack tool, attack surface, and defense mechanism in the same news cycle (Jun 2026)

The first week of June 2026 shows AI tools occupying all three roles in the threat landscape at once, with no clear separation: (1) AI as attack TOOL: An LLM agent was used in-the-wild for post-exploitation after Marimo CVE-2026-39987 — the first documented case, completing credential extraction → SSH → PostgreSQL exfiltration in under an hour (Sysdig); GREYVIBE and Kimsuky (DPRK) both use LLMs to accelerate malware development; a 17M-device botnet used AI chatbot recommendations to redirect users to cryptojacking malware. (2) AI as attack SURFACE: ChatGPhish exploits ChatGPT's implicit Markdown trust for prompt injection phishing via web summaries; codexui-android npm package steals OpenAI Codex authentication tokens; the Malware-Slop campaign targets Claude AI's /mnt/user-data/ workspace directory. (3) AI as DEFENSE: Researcher Calif discovered the HTTP/2 Bomb vulnerability using OpenAI Codex; Microsoft's Codename MDASH is an agentic AI bug-hunting system; Microsoft's ASSERT automates AI safety evaluations; Snowflake's Horizon Catalog includes automatic defenses against jailbreak attempts and zero-day vulnerabilities. The pattern: AI capabilities are not primarily offensive or defensive — they are neutral amplifiers that every actor (attacker, defender, and vendor) is reaching for simultaneously.
