# Required signed OS components create a BYOVD-class primitive that vendors decline to patch

The BTR Reforged case shows a variant of Bring-Your-Own-Vulnerable-Driver that defeats the standard mitigation. Classic BYOVD imports a signed but vulnerable third-party driver, which defenders answer with the Vulnerable Driver Blocklist and WDAC. BTR.sys instead ships inside Windows itself — embedded in Microsoft Defender's MpEngine.dll as the BOOTTIMETOOL resource and present from Windows 7 through Windows 11 25H2 — so it cannot be blocklisted or blocked via WDAC without disrupting Defender. Nothing is exploited in the classic sense: Check Point's Jiří Vinopal reverse-engineered the driver's undocumented transaction protocol, whose configuration blobs are RC4-encrypted with a 256-byte key hard-coded in .rdata and unchanged across 18 unique 64-bit builds since Windows 7, then drove the driver's intended functionality to perform arbitrary Ring 0 file and registry operations.

Two detection lessons generalize. First, the technique registers the driver by direct registry writes (Type=1, Start=1, Group='Boot Bus Extender'), bypassing the Service Control Manager so no Event ID 7045 (Service Installed) is emitted — telemetry keyed to service-installation events misses it entirely. Second, execution happens in a 'golden window' after the filesystem becomes writable but before Defender's user-mode services start, attributed to the System process (PID 4), letting security binaries such as WdFilter.sys and MsMpEng.exe be removed before they can protect themselves. Boot-order timing, not just process identity, is therefore part of the attack surface.

The vendor-response half is the durable governance lesson: because the technique presupposes administrative privileges (SeLoadDriverPrivilege), Microsoft's MSRC ruled it does not meet the criteria for immediate servicing, and Check Point framed it as 'not a vulnerability in the traditional sense, but rather an architectural trust boundary that can be crossed if an attacker already has administrative privileges.' Defenders should not expect a patch for admin-presupposing abuse of legitimate components and must plan detection engineering instead — which Check Point argued is feasible here precisely because no in-the-wild use has appeared yet.

Caveats that must travel with this synthesis: Check Point found no evidence of real-world abuse of BTR.sys in the manner demonstrated, as of the August 20, 2026 publication of the paper and the BTR_CLI proof-of-concept (presented at Black Hat USA 2026 and DEF CON 34). The 'No patch is planned' wording comes from the BTR_CLI GitHub repository and has not been confirmed publicly by Microsoft. The technique requires pre-existing administrative privileges and is not a privilege-escalation path on its own — distinct from CVE-2021-24092, a separate 2021 SentinelLabs finding in the same driver that did allow a local non-administrator to overwrite arbitrary files.
