# AndroidX Security State libraries expose component-level patch status instead of a monolithic Security Patch Level

Google released AndroidX Security State version 1.1.0 and Security State Provider version 1.0.0 as stable. Google describes them as a 'centralized mechanism designed to bring further transparency to the comprehensive security posture and pending updates across the Android ecosystem.'

The substantive change: 'Rather than relying on a coarse, monolithic Security Patch Level (SPL), you can evaluate true component-level protection and whether remediations are actively pending via the androidx.security.state library.' The companion androidx.security.state.provider library lets OEMs and OTA client developers expose update availability via standardized mechanisms.

Audience and consequence: apps with real security stakes — banking, fintech, healthcare — and MDM solutions can now programmatically verify per-component device security state. Note that the two libraries do different jobs and are at different maturity: androidx.security.state (1.1.0) is for apps CONSUMING the state; androidx.security.state.provider (1.0.0) is for OEMs PUBLISHING it, so consumer-side coverage depends on OEM adoption of the provider.
