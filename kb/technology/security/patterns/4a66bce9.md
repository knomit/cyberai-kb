# Three 2026 findings defeat three different phishing-resistant authenticators — passkeys, Windows Hello for Business, and browser session state — without attacking any of them: each operates the credential the endpoint already holds, and all three require malware already running as the user

Three separately disclosed 2026 findings target three DIFFERENT strong-authentication mechanisms and share one mechanism of their own: none breaks the authenticator. Each OPERATES A CREDENTIAL THE COMPROMISED ENDPOINT ALREADY HOLDS AND HAS ALREADY BEEN GRANTED. The cryptography is left intact and simply used.

THE SHARED PRECONDITION, WHICH IS LOAD-BEARING AND MUST NOT BE DROPPED: in all three cases the attacker ALREADY HAS CODE RUNNING AS THE USER ON THE ENDPOINT. None of these is a remote attack on the authentication mechanism, and none of them lets an attacker who lacks that foothold in.

## THE THREE CASES

1. PASSKEYS — Palo Alto Unit 42's 'Pass-ta-key', 'Silver Pass-ta-key' and 'Golden Pass-ta-key' against Chrome's Google Password Manager cloud authenticator. Malware running AS AN ORDINARY USER ON WINDOWS can silently sign into a victim's passkey-protected accounts WITHOUT A FINGERPRINT, PIN, OR ANY ON-SCREEN PROMPT. The source states the mechanism explicitly: 'The attacks do not break the underlying cryptography; instead they target how Chrome stores device keys, re-enrolls devices, and whether sites verify that a human was present.' The three paths can obtain a valid authentication assertion, install an attacker-controlled user-verification key, or extract the 32-byte Security Domain Secret (SDS) used to decrypt synced passkey private keys.

2. WINDOWS HELLO FOR BUSINESS — Entra ID researcher Dirk-jan Mollema demonstrated that malware ALREADY RUNNING IN A SIGNED-IN WINDOWS SESSION can silently use the victim's Windows Hello for Business key to authenticate to Microsoft Entra ID, granting PERSISTENT access.

3. BROWSER SESSION STATE — Amnesia Stealer (Jamf), a macOS stealer delivered via ClickFix, COPIES THE VICTIM'S CHROMIUM PROFILE INCLUDING AUTHENTICATION STATE and loads it into a HEADLESS BROWSER ON THE INFECTED HOST to access authenticated sessions. A Chrome DevTools Protocol streaming module gives the operator a live ~3 fps screencast plus full keyboard, mouse, scroll, navigation and tab control. Jamf assesses it as the first documented macOS malware combining a cloned Chromium profile with CDP-based real-time interactive control.

## WHY THIS IS ONE MECHANISM AND NOT THREE COINCIDENCES

A passkey assertion, a Windows Hello key operation, and a live browser session are all artefacts produced BY a successful authentication. Once an attacker controls the process context in which those artefacts live, re-deriving them is unnecessary — they can be exercised. The corpus already states the consequence for one platform: kb/technology/security/malware/43444425.md records that across 2026 macOS infostealers 'the prize has shifted from files to credentials and live authenticated session state, WHICH DEFEATS PASSWORD ROTATION AND MFA-AT-LOGIN.' These three findings show that consequence is not macOS-specific and not stealer-specific — it holds for the phishing-resistant factors that were adopted precisely to replace passwords.

CORROBORATING, FROM OUTSIDE THIS CLUSTER: kb/technology/security/techniques/browser-session-theft/aceb2a13.md records SpecterOps enabling the Chrome DevTools Protocol inside a LIVE Chromium process on Windows given existing code execution, and states the same shape directly — App-Bound Encryption and device-bound session cookies make stealing and replaying session material harder BUT DO NOT REMOVE THE VALUE OF AN AUTHENTICATED BROWSER, because once CDP is enabled the operator uses the browser's own context to bypass replay protections.

## DEFENSIVE CONSEQUENCE

Controls that harden the ACT of authenticating — requiring a biometric, binding a credential to a device, making a cookie non-replayable elsewhere — do not bind the artefact to a legitimate OPERATOR once the endpoint is under attacker control. What remains available is endpoint integrity itself, and detection of the local abuse: unexpected headless-browser launches, CDP ports opened against a running browser process, browser-profile copies, and Entra ID sign-ins whose device-key use does not correspond to user activity.

## WHAT THIS DOES NOT MEAN — load-bearing

- IT DOES NOT MEAN PASSKEYS, WINDOWS HELLO, OR MFA ARE INEFFECTIVE OR SHOULD NOT BE DEPLOYED. All three findings presuppose an already-compromised endpoint. Against phishing, credential stuffing, and remote attack — the threats these mechanisms were adopted to stop — nothing here shows any weakening. The claim is strictly about what they do and do not bound AFTER endpoint compromise.
- IT DOES NOT CLAIM THE THREE ARE RELATED. Three different researchers, three different platforms and vendors (Chrome/Google Password Manager on Windows; Windows Hello for Business/Entra ID; Chromium on macOS), no shared attribution, infrastructure, or tooling. The connection is the mechanism only.
- EVIDENCE STRENGTH IS UNEVEN. The Windows Hello finding carries confidence 0.6 with one source and is the weakest member; the Unit 42 and Jamf findings carry 0.8 and 0.85 with one source each. None is independently replicated in this corpus, and no in-the-wild exploitation is reported for the Unit 42 or Windows Hello work.
- IT EXCLUDES, DELIBERATELY, the three suspected Russian espionage clusters (UNC6293, UNC7005, UNC5976) that Google describes as 'leveraging legitimate authentication flows'. That activity is persistent adaptive PHISHING and social engineering to compromise personal accounts — it obtains authentication by deceiving the user, not by operating an artefact on an already-compromised endpoint. Folding it in would merge two different mechanisms under one headline.
- SCOPE CONDITIONS MUST SURVIVE CITATION and are not fully reproduced here: the Unit 42 paths are scoped to Chrome's Google Password Manager cloud authenticator on Windows; Amnesia Stealer's delivery is user-executed ClickFix social engineering, not exploitation; and the Amnesia record's fuller inventory of what it steals (16 Chromium-based browsers, passwords, crypto wallets, Apple Notes, documents, iCloud Keychain) is in the source fact.
