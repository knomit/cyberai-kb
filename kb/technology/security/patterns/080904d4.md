# SharePoint Server accumulated at least five separately-exploited flaws in 2026 — three from one July Patch Tuesday — and on 14 July, the day a further actively-exploited zero-day was disclosed, the 2016 and 2019 versions lost extended support with no paid ESU option

This corpus records SharePoint Server vulnerabilities in five separate CVE records plus an end-of-life record, none cross-referencing the others. Read together they state something no one of them states: the product accumulating exploited flaws fastest lost its vendor patching path for two major versions ON THE SAME DAY another actively-exploited zero-day was disclosed.

## THE EXPLOITED FLAWS RECORDED HERE

- CVE-2026-45659 — remote code execution, patched by Microsoft 26 MAY 2026, described as 'exploitable without specialized conditions across multiple SharePoint Server versions'; CISA added it to the Known Exploited Vulnerabilities catalog around 2 JULY 2026 citing active exploitation. (The KEV record carries confidence 0.65 with ZERO recorded sources — the weakest member here.)
- CVE-2026-50522 (CVSS 9.8) — deserialization of untrusted data; came under active exploitation AFTER A PUBLIC PROOF-OF-CONCEPT, per watchTowr. Patched in the July 2026 Patch Tuesday; DEVCORE researcher 'splitline' credited. The source calls it the THIRD SharePoint Server flaw FROM THAT SINGLE UPDATE to be exploited.
- CVE-2026-55040 (CVSS 9.1) — security-feature-bypass from weak authentication allowing impersonation, enabling file disclosure and data modification BUT NOT affecting availability. Patched in the July 2026 Patch Tuesday; per Defused Cyber, exploited in the wild AFTER RAPID7 RELEASED A PROOF-OF-CONCEPT. The source calls it the FIFTH SharePoint vulnerability exploited in 2026.
- CVE-2026-58644 (CVSS 9.8) — deserialization of untrusted data allowing remote arbitrary code execution; added to KEV 16 JULY 2026 with FCEB remediation required by 19 JULY 2026. Exploitable over the internet with LOW ATTACK COMPLEXITY (no significant prior knowledge needed, repeatable payload success).
- CVE-2026-56164 — an actively exploited SharePoint Server zero-day disclosed 14 JULY 2026. THIS CORPUS HOLDS NO STANDALONE RECORD OF IT; it is named only inside the end-of-support record.

## THE PRECONDITIONS VARY AND MUST NOT BE FLATTENED
CVE-2026-58644 and CVE-2026-50522 both require an attacker AUTHENTICATED AS AT LEAST A SITE OWNER. CVE-2026-55040 is an authentication bypass permitting impersonation. CVE-2026-45659 is described as needing no specialized conditions. These are different entry requirements and a defender cannot treat them as one.

On whether the Site Owner requirement is protective, kb/technology/security/patterns/22a65270.md is directly on point and reaches a specific conclusion: a precondition is not protective in itself, and what matters is HOW MANY REAL TARGETS SATISFY IT — noting that 'someone holds Site Owner' is true in almost every tenant of any size, and that CVE-2026-50522 was exploited despite carrying that requirement.

## THE CONJUNCTION THAT IS THE ACTUAL FINDING
14 JULY 2026 was BOTH the day Microsoft disclosed the actively exploited zero-day CVE-2026-56164 AND the end of extended support for SHAREPOINT SERVER 2016 AND 2019. Unlike Windows Server or SQL Server, NEITHER of those SharePoint versions has a paid Extended Security Update programme to fall back on, leaving SELF-HOSTED OPERATORS OF THOSE VERSIONS WITHOUT A VENDOR PATCHING PATH. SharePoint has been a persistent attacker target since the ToolShell exploit chain tore through unpatched servers in 2025.

NOTE THAT TWO DIFFERENT MECHANISMS ARE IN PLAY HERE and this record does not merge them. The CVE-2026-50522 and CVE-2026-55040 cases are exploitation-outpaces-patching: a patch existed and attackers moved faster than deployment, in both cases after a public PoC. The end-of-support case is the opposite shape: for 2016 and 2019 there will BE no further patch to outpace.

## WHAT THIS DOES NOT MEAN — load-bearing

- THE COUNTS ARE THE SOURCE RECORDS' OWN. 'Fifth SharePoint vulnerability exploited in 2026' and 'third from that update' are claims made inside individual records, not independently verified, and this corpus does not enumerate the full five. Do not read the list above as complete or as the specific five referred to.
- THE ESU GAP APPLIES TO SHAREPOINT SERVER 2016 AND 2019 SPECIFICALLY. It says nothing about SharePoint Online or later self-hosted versions, which retain a supported patching path. A reader must not generalise 'SharePoint is unpatchable' from this.
- IT DOES NOT CLAIM THE TIMING WAS INTENTIONAL OR CAUSAL. That a zero-day disclosure and an end-of-support date fell on the same day is a co-occurrence the sources record; no source states any connection between them, and none is inferred here.
- IT DOES NOT CLAIM SHAREPOINT IS UNIQUELY INSECURE. This corpus selects for notable disclosures and holds no comparative base rate across enterprise collaboration platforms, so 'accumulating exploited flaws fastest' describes what is RECORDED here, not a measured ranking.
- IT DOES NOT ESTABLISH THAT PUBLIC PoC RELEASE CAUSED EXPLOITATION. Two records state exploitation followed a PoC; kb/technology/security/patterns/22a65270.md separately establishes across four 2026 cases that DISCLOSURE ALONE DOES NOT DETERMINE EXPLOITATION, with published exploits followed by mass exploitation in one case and nothing at four weeks in another.
- PER-CVE DETAIL MUST BE TAKEN FROM THE SOURCE FACTS: CVSS scores, patch dates, KEV addition and remediation deadlines, discoverers, and the precise impact wording (notably that CVE-2026-55040 does not affect availability).
