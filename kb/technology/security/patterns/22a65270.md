# Published detail did not determine exploitation across three 2026 flaws; precondition breadth tracked it better, though not decisively

This corpus holds several records in which exploitation followed the publication of technical detail or a proof-of-concept, which invites the rule 'publication leads to exploitation'. Three 2026 cases written up by the same research firm show that rule is not what the evidence supports — and the third shows the better rule is not clean either.

EXPLOITED AT SCALE, NO PRECONDITION. 'wp2shell' chains CVE-2026-63030 and CVE-2026-60137 into pre-authenticated RCE in WordPress Core via the REST batch API. Per the record it 'can be exploited anonymously on a STANDARD WORDPRESS INSTALLATION WITH NO PLUGINS OR SPECIAL CONDITIONS REQUIRED', achieving full site compromise. By 18 July 2026 the flaws had CVE IDs, the full mechanism was published and a working PoC was public; mass exploitation began in the early hours of a Saturday UTC, first using public exploit code to exfiltrate hashed credentials, with RCE following as further details emerged.

NOT EXPLOITED, PRECONDITION PRESENT. CVE-2026-8037 in Progress Kemp LoadMaster is CVSS 9.8 — HIGHER-RATED — and lets an unauthenticated attacker run commands as root, but only 'VIA A CRAFTED API REQUEST WHEN THE API IS ENABLED'. It was reported via ZDI on 15 April 2026, the advisory published 4 June, and watchTowr Labs published a technical exploit write-up on 29 June. The record states: no in-the-wild exploitation reported.

THE COMPLICATION — EXPLOITED DESPITE A PRECONDITION. CVE-2026-50522 (CVSS 9.8), a deserialization flaw in Microsoft Office SharePoint Server, 'came under active exploitation AFTER A PUBLIC PROOF-OF-CONCEPT' — and it requires 'a network attacker AUTHENTICATED AS AT LEAST A SITE OWNER'. That is a real precondition, and it did not prevent exploitation. It was the third SharePoint Server flaw from the same July 2026 Patch Tuesday to be exploited.

WHAT THIS SUPPORTS AND WHAT IT DOES NOT. Across the three, published technical detail was present in every case and the outcomes differed, so DISCLOSURE ALONE DOES NOT DETERMINE EXPLOITATION — that much holds. Precondition breadth orders the three better than severity does (the unexploited case has the joint-highest CVSS), but the SharePoint case shows a precondition is not protective in itself: what matters is how many real targets satisfy it. 'The API is enabled' is a deployment choice a minority make; 'someone holds Site Owner' is true in almost every tenant of any size. So the usable form of the rule is about the SIZE OF THE POPULATION THAT SATISFIES THE PRECONDITION, not the presence of one — and that quantity is rarely stated in an advisory, which is precisely why the cheap proxies get used instead.

RELATED AND POINTING THE SAME WAY FROM THE OTHER SIDE: kb/technology/security/patterns/7cd2242c.md records August 2026 exploitation of critical enterprise-infrastructure flaws arriving within days of patch, SOMETIMES WITH NO PUBLIC PoC AT ALL. If exploitation can precede or bypass public exploit code entirely, disclosure is neither necessary nor sufficient.

SCOPE AND CAVEATS: THIS IS THREE CASES, one of them a NEGATIVE observation — 'no in-the-wild exploitation reported' is absence of evidence and could reflect reporting gaps or a shorter observation window, and the LoadMaster write-up is the most recent of the three. The LoadMaster record carries sources: 0 in this corpus. Exposure counts differ enormously between WordPress, SharePoint Server and a commercial load balancer, so installed-base size is confounded with precondition breadth throughout and this record cannot separate them. WHAT THIS DOES NOT MEAN: this does NOT claim publishing technical detail is harmless or that disclosure timing is irrelevant — the corpus separately records exploitation beginning within days, and in some cases hours, of details becoming public. It does not claim preconditions are worthless as a filter. It claims that disclosure is not sufficient, that severity ordered these three wrongly, and that the population satisfying the precondition is the variable worth estimating — while acknowledging that three cases cannot establish a rate.
