# The same endpoint sensor is going blind and going noisy at once: adversaries operate inside VMs it cannot see while benign coding agents trip the rules written for intruders

Two 2026 findings from the same vendor's endpoint telemetry describe opposite failure modes of one control, and reading them together changes what the control is worth.

BLIND ON ONE SIDE. Two threat clusters abuse QEMU, an open-source machine emulator, to run malicious activity inside virtualised environments invisible to endpoint security. STAC4713 uses QEMU as a covert reverse-SSH backdoor — likely ex-BlackBasta affiliates entering via SolarWinds Web Help Desk flaws and aiming to deploy Payouts King ransomware. STAC3725 exploits Citrix Bleed 2 (CVE-2025-5777) for initial access, installs ScreenConnect, then stands up a QEMU VM for enumeration and credential theft. The sensor is on the host; the activity is in the guest.

NOISY ON THE OTHER. A week of the same vendor's endpoint telemetry found AI coding agents — Claude Code, Cursor, OpenAI Codex — triggering detection rules written to catch human attackers, even though the agents are not malicious. The behaviours those rules key on (spawning shells, reading widely across a filesystem, driving developer tooling at machine speed) are what a coding agent legitimately does.

WHAT FOLLOWS: these are not two unrelated complaints about one product. They are the same property seen from both ends — the rules describe BEHAVIOUR ON THE HOST, so anything that moves off the host disappears, and anything new that behaves like the adversary profile lights up. Adding agents to a fleet therefore raises alert volume in the same period that adversaries have a documented way to generate none, and the analyst attention consumed by the first is not available for the second. A team measuring its detection programme by alert counts will read both changes as the programme working harder.

SCOPE AND CAVEATS: both findings are from ONE vendor (Sophos) and neither is a measured rate — the agent-noise record is a single week of that vendor's own telemetry and carries sources: 0 in this corpus; the QEMU record describes two named clusters, not a prevalence estimate. The attention-budget consequence stated above is an INFERENCE from the conjunction, not something either source measured; no study here quantifies analyst time lost to agent false positives or incidents missed inside guests. WHAT THIS DOES NOT MEAN: this does not claim the two are causally linked, that the same actors exploit both, or that endpoint detection is not worth running — the QEMU clusters still had to get onto the host first, by exploiting named flaws that host-level controls can catch. Nor does it claim agent alerts are always false: the point is that the rules cannot tell, which is why the volume grows.
