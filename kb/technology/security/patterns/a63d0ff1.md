# Session theft is shifting from exfiltrating cookies to driving the victim's own authenticated browser via CDP

Two independent August 2026 findings — one offensive research technique, one malware family in the wild — converge on the same operating model: rather than stealing cookie material for replay elsewhere, the attacker uses the Chrome DevTools Protocol to operate an authenticated browser in the victim's own context.

Research side (SpecterOps, Windows): a post-exploitation technique enables CDP inside a live Google Chrome or Microsoft Edge process, given the attacker already has code execution on the host, to steal cookies, saved data and authenticated browser sessions. SpecterOps notes that App-Bound Encryption and device-bound session cookies make stealing and replaying session material harder but do not remove the value of an authenticated browser — once CDP is enabled, an operator uses the browser's own context to bypass replay protections, suggesting the next evolution of cookie theft may not require stealing the cookie DB or ABE key at all.

In-the-wild side (Jamf, macOS): Amnesia Stealer, delivered via ClickFix attacks, steals data from 16 Chromium-based browsers plus passwords, crypto wallets, Apple Notes, documents and iCloud Keychain — and additionally copies the victim's Chromium profile including authentication state into a headless browser on the infected host to access authenticated sessions. A CDP-based streaming module gives the operator a live ~3fps screencast plus full keyboard, mouse, scroll, navigation and tab control. Jamf assesses it as the first documented macOS malware to combine a cloned Chromium profile with CDP-based real-time interactive control.

Defensive implication: controls designed around the cookie as the stolen artifact (App-Bound Encryption, device-bound session cookies, impossible-travel and device-fingerprint checks on replay) do not address an operator driving the legitimate browser on the legitimate device. Detection has to move toward CDP enablement and anomalous headless/debug-port activity in browser processes.

WHAT THIS DOES NOT MEAN: the SpecterOps technique is not a vulnerability and confers no initial access — it presupposes existing code execution on the host, so it is a post-exploitation capability, not an entry vector. It also does not mean ABE and device-bound cookies are worthless; they still raise the cost of ordinary offline cookie replay.
