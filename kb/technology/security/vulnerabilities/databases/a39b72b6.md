# CVE-2026-23479: Redis RCE (CVSS 8.8) found by autonomous AI tool — 2-year-old UAF in blocking-client code

Redis patched a use-after-free (UAF, CWE-416) in its blocking-client code tracked as CVE-2026-23479 (CVSS 8.8 / NVD; 7.7 / Redis CVSS 4.0). Discovered by an autonomous AI bug-hunting tool built by Team Xint Code to hunt bugs in large codebases — the first major public example of a fully autonomous AI tool finding and fully documenting a critical database vulnerability. Impact: authenticated user can run arbitrary OS commands on the database host. Wiz analysis: Redis is in a large majority of cloud environments, and in default deployment the default user already holds every privilege the exploit chain requires (no password needed). Introduced: two commits created the bug — a January 2023 refactor (PR #11012) added the unchecked call; a March 2023 change (PR #11568) added more client access after it. Neither was dangerous alone; together they reached GA in Redis 7.2.0 and survived multiple rounds of security review undetected for over 2 years. Code path: `unblockClientOnKey()` in `src/blocked.c` → `processCommandAndResetClient()` frees the client as a side effect, then reads the freed structure. 3-stage exploit: (1) Lua one-liner leaks heap pointer; (2) groomed client memory + pipelined SET reclaims freed slot with fake client structure; (3) `updateClientMemoryUsage()` performs out-of-bounds decrement via attacker-controlled fields aimed at the Global Offset Table to overwrite a function pointer. Patched in May 5, 2026 Redis releases; full technical write-up public.
