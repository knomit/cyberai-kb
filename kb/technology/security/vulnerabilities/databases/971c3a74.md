# PostgreSQL CVE-2026-6471 lets REPLICATION-role accounts execute OS code via logical decoding

PostgreSQL patched CVE-2026-6471 (CVSS 7.2), nicknamed PostGREShell, a flaw present since logical decoding was introduced in PostgreSQL 9.4 in 2014. An account holding the REPLICATION attribute can load an arbitrary library as a logical decoding output plugin and run code as the operating-system user that runs the database server. Exploitation requires both conditions together: an account carrying the REPLICATION attribute and a server running with wal_level = logical. Backup tools, standby servers, change data capture pipelines, and monitoring systems routinely hold that attribute, so the privilege is common in practice. Versions before 18.6, 17.11, 16.15, 15.19, and 14.24 are affected; the fix shipped August 13, 2026 and adds a server parameter output_plugin_libraries listing which libraries may be loaded as output plugins, defaulting to 'pgoutput, test_decoding'. Sites using third-party output plugins (Debian names wal2json and decoderbufs) must explicitly add them to output_plugin_libraries after updating or those plugins stop working.
