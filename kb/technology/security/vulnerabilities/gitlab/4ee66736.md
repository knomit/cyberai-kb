# GitLab CVE-2026-19478: critical GraphQL directive flaw, exploited in the wild within days

GitLab issued an out-of-band critical patch release on 2026-08-17 for CVE-2026-19478 (CVSS 9.4), affecting Community and Enterprise Edition. Under certain conditions the flaw lets an unauthenticated attacker remotely modify or delete public projects and user data via a GraphQL directive, exploitable over the network with no credentials, no victim interaction and no obscure configuration. Fixes shipped in GitLab 19.2.4, 19.1.6, 19.0.8, and 18.11.11; affected ranges are all versions from 18.2 before 18.11.11, 19.0 before 19.0.8, 19.1 before 19.1.6, and 19.2 before 19.2.4. The 18.2-18.10 branches did not receive fixes despite falling in the affected range. Only self-managed installations need to act; GitLab.com and GitLab Dedicated already run patched versions. A second issue, CVE-2026-19650 (CVSS 7.1, High), is a CSRF weakness in the GraphQL multiplex query handler.

UPDATE (reported 2026-08-22, superseding the earlier 'no known exploitation as of 2026-08-18' status): watchTowr told The Hacker News it reproduced the vulnerability within minutes of disclosure and observed in-the-wild exploitation against its honeypot network. watchTowr said impact extends beyond modifying or deleting public projects — an attacker can delete entire repositories, forge merge records to make it appear a fix landed when it did not, and ban project maintainers. Principal security researcher Jake Knott advised unpatched organizations to hunt web logs for requests containing '@gl_introduced', and framed the case as evidence that AI-enabled attackers are compressing the interval from disclosure to exploitation, making 'wait for the next patch cycle' an unsafe default.
