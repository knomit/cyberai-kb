# GitLab self-managed 18.11.3 RCE via Jupyter-notebook diff chain (PoC, July 2026)

On July 24, 2026, researchers at depthfirst published working exploit code for a remote code execution flaw in GitLab that GitLab had quietly patched six weeks earlier on June 10, 2026. The exploit runs commands as the git user on any self-managed 18.11.3 server that has not applied the update. Any authenticated user who can push to a project can trigger it: the attacker commits a crafted Jupyter notebook and opens its commit diff, which leaks a heap pointer; repeated leaks let an automated probe locate libraries in memory, then two more notebooks fire the payload. No administrator rights, CI/runner access, or victim interaction are needed. Notably GitLab did not file the fix as a security fix — the Oj 3.17.3 dependency bump was listed under bug fixes in the June 10 release with no CVE and no CVSS score, so operators triaging against the security table had no reason to treat it as urgent.
