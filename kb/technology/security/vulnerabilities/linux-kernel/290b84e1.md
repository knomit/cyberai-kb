# Four Linux kernel local-root flaws (DirtyAH6, TUNderflow, PPPoEject, DiagSpill) have public working exploits as of 2026-09-18

Researcher Asim Manizada published a technical write-up with working exploit code on 2026-09-18 for four Linux kernel local privilege escalation flaws, each allowing a local user to gain root. He reported them to the Linux kernel security team in mid-July 2026 and held publication under coordinated disclosure with Linux distributions until fixes shipped; all four are fixed in current kernels, so an up-to-date kernel is not affected. The four: DirtyAH6 (CVE-2026-80844, IPsec AH6/IPv6), TUNderflow (CVE-2026-81000, TUN/TAP virtual network devices), PPPoEject (CVE-2026-68121, PPPoE), and DiagSpill (CVE-2026-74469, SCTP sctp_diag). The precondition differs between them and the distinction is the operationally important part: DirtyAH6, TUNderflow and PPPoEject are reachable by an ordinary user ONLY when unprivileged user namespaces are enabled (many distributions enable them by default, which is how the attacker obtains the network privileges the exploits require); DiagSpill is the exception, requiring no user namespaces and no special privileges as long as the SCTP networking module is available. Two of the four have narrow remote reachability and only for denial of service: DirtyAH6 can crash a host that routes IPv6 and adds an IPsec Authentication Header in transport mode, and DiagSpill can crash a host only when non-default SCTP options are enabled. Manizada achieved remote root with DirtyAH6 only in his own lab and only after shaping memory on the target first, writing that doing so from a remote position alone 'looks extremely difficult' though he did not rule it out; for DiagSpill he sees no path to remote root. No in-the-wild exploitation has been reported. The published exploits are tuned to specific kernel builds and can crash a machine, so they are intended for isolated test systems. Operational consequence: prioritize kernel updates on multi-user and shared systems where an attacker may already hold a low-privileged account. This does NOT mean these are remotely exploitable for code execution — remote reach is crash-only and conditional.
