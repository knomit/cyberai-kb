# Linux local-root flaws recur in optional kernel subsystems that ship enabled by default, so stock installs are exposed without any administrator opt-in

Mechanism: a latent defect in an optional kernel subsystem becomes reachable by any unprivileged local user because the distribution enables that subsystem by default, so exposure is determined by the vendor's default configuration rather than by anything the administrator chose to turn on.

Two independently reported instances in this corpus instantiate the shape: one in a virtual-networking datapath and one in a filesystem, each giving an ordinary local user a path to root on default-configured distributions, and each with the defect having gone unnoticed in shipped kernels for an extended period before disclosure. See the cited members for the specific subsystems, CVE identifiers, affected distributions, disclosure dates, and exploit availability — the provenance stays with them.

Operational consequence: when triaging a kernel local-privilege-escalation advisory, the question that determines your exposure is whether the affected subsystem is enabled in your distribution's default build, not whether you deliberately configured or use that subsystem. Disabling or blacklisting an unused default-enabled subsystem removes the reachability that the default provided.

WHAT THIS DOES NOT MEAN: it does not mean every kernel subsystem is enabled by default or that every kernel LPE is reachable on a stock install — reachability is per-flaw and per-distribution and must be checked against the specific advisory. It also does not claim any measured base rate; two reported instances establish a recurring shape worth checking for, not a frequency.
