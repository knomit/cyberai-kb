# Claude for Chrome v1.0.80 honors forged clicks, letting rogue extensions trigger Gmail, Docs and Calendar tasks

Manifold Security reported that any browser extension able to run a script on claude.ai can trigger Claude for Chrome tasks that read the user's Gmail, latest Google Doc and its comments, and Calendar. After the earlier ClaudeBleed flaw, Anthropic restricted external callers in May 2026 to nine fixed task IDs baked into the extension bundle (three onboarding practice prompts, three for DoorDash/Salesforce/Zillow, and usecase-gmail, usecase-gdocs, usecase-calendar). The allowlist holds, but the trigger does not: a content script listens on claude.ai for a click on the element #claude-onboarding-button, reads its data-task-id, and forwards allowlisted IDs to the extension via an open_side_panel message — without checking whether the click was genuine. Manifold demonstrated the attack with six lines pasted into the claude.ai console, with isTrusted:false in the logs confirming the synthetic click was honored. Manifold rates it CVSS 7.7 High in the default 'ask before acting' mode (an approval box still stands in the way) and CVSS 9.6 Critical once a user enables 'Act without asking', where the task runs silently. A second, not-currently-reachable issue: loading Claude's side panel with ?skipPermissions=true boots it straight into skip_all_permission_checks. The Hacker News independently unpacked the current build and confirmed both mechanisms remain in v1.0.80, eight versions after the May restriction. The researchers' proposed one-line fix — rejecting synthetic clicks at the top of the handler — has not shipped. Mitigation: disable 'Act without asking' and audit extensions with permission to read or change data on claude.ai.
