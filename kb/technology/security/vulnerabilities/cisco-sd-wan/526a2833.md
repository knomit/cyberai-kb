# Catalyst SD-WAN Manager drew three distinct exploited flaws in 2026, with preconditions ranging from privileged-local to unauthenticated-remote — patching any one did not end the exposure

MECHANISM: a centralized management plane that controls many downstream devices is exploited repeatedly through distinct, unrelated flaws, so remediating any one flaw does not end the product's exposure.

The corpus records three separate, actively exploited vulnerabilities in the same management product during 2026, each a different bug with a different precondition:
- one requiring an AUTHENTICATED, REMOTE attacker who ALREADY holds valid credentials with at least write access (file upload → arbitrary file write → root);
- one requiring an AUTHENTICATED LOCAL attacker holding NETADMIN privileges, exploited as a zero-day for at least two months before disclosure with anti-forensics;
- one requiring NO authentication, giving REMOTE unauthenticated attackers admin-privileged API access, also exploited as a zero-day, with no workaround and internet-exposed instances at immediate risk.

CONSEQUENCE: treat exposure of this class of management plane as a standing risk rather than a per-CVE event — limit internet reachability and privileged accounts, and do not read 'patched the last advisory' as 'no longer exposed'.

WHAT THIS DOES NOT MEAN: the three flaws are recorded as DISTINCT (the latest advisory says so explicitly); nothing here establishes a common actor, a common root cause, or that one exploitation enabled another. The sequence of preconditions (privileged → unauthenticated) is an observation about these three records, not a trend claim. Three instances in one product is not a measured rate, and other vendors' management planes are not covered by this record.
