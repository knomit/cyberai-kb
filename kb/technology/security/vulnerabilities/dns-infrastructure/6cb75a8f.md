# BIND 9.20.29 and 9.21.26 fix fourteen flaws including an unauthenticated DoH crash

On 16 September 2026 the Internet Systems Consortium (ISC) disclosed fourteen security flaws in BIND 9 and released BIND 9.20.29 (fixes all fourteen), BIND 9.21.26 (fixes thirteen; CVE-2026-19662 does not affect the 9.21 branch), and BIND 9.20.29-S1 Supported Preview Edition (fixes all fourteen). ISC said it is not aware of any of the fourteen being exploited, and listed no workarounds. Only TWO of the fourteen can be triggered by a request alone, without the attacker operating their own DNS server, and both affect only the 9.20 and 9.21 branches: CVE-2026-77692 crashes named on any BIND server answering DNS-over-HTTPS when an unauthenticated sender submits a request carrying an invalid SIG(0) signature AND closes the connection before named finishes checking that signature — both components are required; and CVE-2026-76163 crashes named on a TKEY-type query only when the server's named.conf has no global options block. The remaining crashes require a recursive resolver to receive crafted data from an attacker-controlled server: CVE-2026-19667 (default configuration), CVE-2026-19666 (dns64 with break-dnssec yes), CVE-2026-80274 (validating resolver receiving a wildcard answer carrying both NSEC and NSEC3 proofs), and CVE-2026-19662 (specific answer order and timing; 9.20 only). Operational consequence: a DoH-answering BIND server on 9.20 or 9.21 is remotely crashable by an unauthenticated party and should be patched first. This does NOT mean all fourteen flaws are remotely triggerable by a bare request — twelve need attacker-controlled DNS infrastructure or a specific non-default resolver configuration.
