# Host-kernel use-after-free bugs break both VM and container isolation because the kernel is the shared boundary (Sept 2026)

Mechanism: when a confined workload (VM guest or container) can drive a code path in the shared host kernel that uses freed memory, the isolation layer offers no protection, because the bug lives in the very component enforcing the boundary; the confined workload gains read/write of host memory or host root. Two Sept 2026 Linux kernel disclosures instantiate this: CVE-2026-89775 in ARM64 KVM lets a guest read and write host kernel memory and escape to the host; CVE-2026-80521 in the AF_UNIX socket garbage collector lets a container escape to host root. Load-bearing conditions carried from members: the KVM flaw requires BOTH ARM64 hardware with Armv8.4 FEAT_NV2 AND nested virtualization enabled (off by default, experimental boot-time mode); it is fixed upstream, and where any user can open /dev/kvm a local user can also use it for root. The AF_UNIX flaw is reachable through ordinary syscalls containers are allowed, so namespaces, cgroups and seccomp do not stop it; it was fixed upstream but Ubuntu 26.04/24.04/22.04 LTS were unpatched at disclosure, with public exploit code for 26.04 and no published workaround. Consequence: for multi-tenant hosts, kernel patch latency (including distribution lag behind upstream) is the effective isolation guarantee. WHAT THIS DOES NOT MEAN: it does not claim either flaw was exploited in the wild (neither was reported as such), nor that all KVM hosts are exposed — the KVM bug is confined to the stated ARM64 nested-virt configuration.
