# Writing values back into a structured format without escaping turns data into markup that reaches code execution (SharePoint and Next.js, Sept 2026)

Mechanism: a component re-emits caller-influenced values into a structured text format without escaping that format's delimiters, so a crafted value is re-parsed as structure rather than data, and the downstream consumer that trusts the re-emitted structure executes it. Two September 2026 disclosures instantiate this: SharePoint's ToolPane reconstructs Register directives by writing attribute values between double quotes without escaping embedded quotes, undermining the SafeControls check and yielding authenticated RCE; Next.js ImageResponse (via Satori) placed certain values into generated SVG unescaped, yielding server code execution. Load-bearing conditions carried from members: the SharePoint flaw requires an authenticated (authorized) attacker; the Next.js flaw applies only to Next.js 16.2.0-16.3.5 with ImageResponse on the Node.js runtime AND only in apps that pass attacker-controlled values into SVG content, attributes or styles (Edge runtime and Next.js 15 unaffected). Neither had reported in-the-wild exploitation at disclosure. Consequence: the SharePoint case also shows vendor severity labels can hide this class (advisory said spoofing, CVSS 6.5; actual impact RCE), so triage should key on root cause, not the advisory headline. WHAT THIS DOES NOT MEAN: it does not claim the two share code or a common library, and it does not cover sanitize-at-save/transform-at-display gaps (e.g., WordPress Comment2Shell), which are a related but distinct mechanism.
