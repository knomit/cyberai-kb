# Cursor on Windows executes an attacker-supplied git.exe from a cloned repository root with no patch available

AI security firm Mindgard disclosed on 2026-07-14 that Cursor on Windows will execute a file named git.exe placed in a project's root directory simply upon opening the repository — no click, no approval dialog, no prompt injection, no agent or model in the loop. Cursor probes several locations for a Git binary when a project loads, one of which is the workspace itself; Process Monitor output shows Cursor.exe spawning the repo-root binary with the command line 'git rev-parse --show-toplevel', the same repository-root probe VS Code documents. The result is arbitrary code execution as the logged-in user, re-triggered for as long as the project stays open. Mindgard's PoC was Windows Calculator renamed to git.exe and committed to the repo root. Mindgard reported the flaw to Cursor on 2025-12-15 and published full technical details seven months later; as of 2026-07-15 there is still no patch, no Cursor advisory, and no assigned CVE. Mindgard's most recent dated confirmation was 2026-04-30 against Cursor 3.2.16 (current release 3.11). Recommended workarounds are AppLocker or Windows App Control path-based deny rules under workspace roots, or opening untrusted repositories in a disposable VM or Windows Sandbox.
