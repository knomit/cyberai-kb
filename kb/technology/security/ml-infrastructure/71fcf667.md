# Mid-August 2026: the AI/ML stack itself — not just AI-written code — was the week's concentrated attack surface, across four distinct layers

Within a single week (2026-08-15 to 2026-08-18) four independently reported security events all landed on components of the AI/ML stack rather than on general enterprise software, spanning four distinct layers:

1. **Compute/orchestration layer.** CISA added CVE-2025-62593 (CVSS 9.4) in Ray — the open-source Python-native distributed computing framework for AI/ML workloads — to its KEV catalog on 2026-08-17 citing active exploitation. RCE via DNS rebinding from a browser, rooted in Ray's longstanding decision not to authenticate critical endpoints (/api/jobs, /api/job_agent/jobs/). Fixed in Ray 2.52.0; FCEB remediation deadline 2026-08-20. Oligo reports unpatched Ray clusters with NVIDIA GPUs conscripted into a self-replicating cryptomining botnet (ShadowRay 2.0).

2. **Experiment-tracking layer.** watchTowr and VulnCheck independently reported scanning and exploitation of CVE-2026-64849 (CVSS 9.3), an unauthenticated SSRF in MLflow allowing anyone who can reach the Tracking Server to hit arbitrary internal cloud metadata endpoints and extract secrets (versions below 3.15.0). Reported alongside FUXA CVE-2026-25895 (CVSS 9.5), an OT/SCADA flaw, in the same advisory wave.

3. **Assistant layer.** Varonis disclosed CoSnitch (CVE-2026-24301), three flaws in Microsoft Copilot Personal enabling one-click silent exfiltration from connected apps, patched 2026-08-18 after a December 2025 report. Scope note carried from source: the research names Copilot Personal (copilot.microsoft.com) and does not state Microsoft 365 Copilot was affected; no in-the-wild exploitation was found.

4. **Agent-state layer.** An Anthropic/EPFL preprint (2026-08-10) demonstrated self-propagating payloads spreading between AI agents through persistent system-prompt files (SOUL.md), with an 88%-of-attempts / 55%-infection profile for that file versus 12%/17% for ordinary workspace files. Scope note carried from source: there is no evidence the technique has spread in the wild, and a review of archived Moltbook posts found no successful agent-to-agent propagation.

The common thread is a default-trust posture inherited from research tooling: Ray declined authentication on job endpoints by design, MLflow's Tracking Server accepted unauthenticated requests, and agent harnesses inject writable state files into the system prompt without provenance marking. Each was acceptable in a single-developer research context and became a production attack surface when the same components moved into enterprise deployment.

WHAT THIS DOES NOT MEAN: this does not claim these four events share an actor, a campaign, or a causal link — they are independent disclosures that happened to cluster in one reporting week, drawn from one newsletter's coverage, which selects for notable security news. It does not establish that AI infrastructure is less secure than comparable non-AI infrastructure; no base-rate comparison was made. The Ray and MLflow items involve confirmed active exploitation; the Copilot and agent-propagation items explicitly do not.
