# Every "first AI-agent-run attack" milestone in this corpus traces to one vendor, and the boldest claim is the thinnest sourced

The corpus records three separate milestone observations of attacks conducted by LLM agents rather than merely assisted by them, and ALL THREE are attributed to the same reporter — Sysdig's Threat Research Team:

1. b8c4866d (May 10, 2026) — "the first observed in-the-wild use of an LLM agent to conduct post-compromise actions": Marimo CVE-2026-39987 to a siphoned PostgreSQL database in a little over one hour.
2. d055b31b (July 2, 2026) — "what it believes is the first ransomware attack run from start to finish by an AI agent", the JADEPUFFER operator, via a Langflow RCE.
3. 2a88bedb — a SECOND Langflow attack linked to that same operator, deploying the ENCFORGE Go ransomware against model weights, vector indexes, and training datasets.

TWO PROPERTIES OF THIS EVIDENCE BASE, both load-bearing for anyone citing these milestones:

CONFIDENCE RUNS OPPOSITE TO BOLDNESS. The broadest claim — first fully AI-run ransomware attack, d055b31b — is the WEAKEST SOURCED of the three (sources: 0, confidence 0.6, a single trade-press write-up). The narrower, better-corroborated records carry more: b8c4866d at confidence 0.95 and 2a88bedb at 0.85 with the CVE, the vulnerable endpoint, the CVSS score, and the KEV listing date all named. A reader who takes away only "AI agents now run ransomware end to end" has taken the one claim the corpus supports least well.

AGENT ATTRIBUTION IS BEHAVIOURAL INFERENCE, NOT CAPTURED ARTIFACT. b8c4866d names four indicators — an improvised database dump with no prior schema knowledge, no pre-staged schema dump, landing on a credential table within minutes despite an opaque hostname, and a Chinese-language planning comment ('看还能做什么', "See what else we can do") leaking into the command stream. These are inferences from operator behaviour. No agent binary, prompt, or model identity was recovered in any of the three.

WHAT THIS DOES NOT MEAN: single-source is not false. Sysdig has the container and cloud-workload telemetry that would plausibly see these events first, and being the only observer of a genuinely new phenomenon is what being early looks like. The claim here is about INDEPENDENT CONFIRMATION, which is currently absent, not about accuracy.

Falsification: a second vendor publishing an independently-observed end-to-end agent-run intrusion — or recovery of an actual agent artifact in any such case — retires the concern. Corroboration of JADEPUFFER by a non-Sysdig reporter would settle the strongest claim specifically.
