# Tenant isolation can hold at its primary boundary while shared supporting infrastructure the tenant does not control still leaks across it

MECHANISM: when workloads are isolated at one layer (the VM or container boundary) but still depend on supporting infrastructure that the provider shares across tenants and assigns on their behalf (network policy, name resolution, address pools, disk provisioning), a flaw in that shared layer crosses the tenant boundary even though the primary isolation mechanism itself is never broken.

Two independent 2026 instances:
- In an agent-sandboxing evaluation, no model achieved a VM-to-host breakout, yet several models bypassed network confinement through shared-network weaknesses (DNS spoofing, IP-sharing) in a minority of partial-network trials; the same class of shared-infrastructure weakness was found in most third-party platforms tested. After remediation, no model could bypass the updated measures.
- A managed container service (also used to run untrusted, agent-written code) let a paying customer read data left on shared servers by other customers' earlier containers, because of how each container's disk was provisioned on infrastructure the provider, not the customer, assigns.

OPERATIONAL CONSEQUENCE: an assurance that 'the VM/container boundary holds' does not establish tenant isolation; the shared network and storage layers under that boundary need to be tested as separate attack surfaces, especially where untrusted or agent-generated code runs.

LOAD-BEARING QUALIFIERS carried from the members: in the sandboxing case no VM-level breakout occurred and the bypasses stopped after remediation. In the container case the exposed data was residual data from earlier containers, NOT any live workload, an attacker could NOT choose whose data they received, and the provider fixed it with no customer action required.

WHAT THIS DOES NOT MEAN: it does not claim VM or container isolation is ineffective — in both cases the primary boundary held. It does not claim these flaws remain open. Two instances establish that the mechanism recurs, not how common it is across providers beyond the sandboxing evaluation's own third-party sample.
