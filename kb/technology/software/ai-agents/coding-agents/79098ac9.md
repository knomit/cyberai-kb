# Independently built coding agents converge on the same core loop: read, edit, execute, persist session, gate side effects

MECHANISM: when independent producers build tools for the same task shape, they converge on the same architecture, because the task's structure rather than the underlying model determines the design.

Coding agents shipped by unrelated organizations — a large platform vendor, an independent model lab, and an open-source model host — share a common core despite no shared codebase or lineage: the agent reads project files, edits code, runs shell commands in the developer's own environment, and checks the result, iterating on feedback rather than emitting one answer. Two further elements recur: persistent or durable session state so work survives beyond a single exchange, and an explicit boundary around side effects (approvals, a sandbox, or verification before acting) rather than unrestricted execution.

WHAT THIS DOES NOT MEAN: convergence on architecture is not convergence on maturity or purpose. The members differ materially in what they are for — one is an explicitly pedagogical reference implementation, to be read as a teaching project rather than a production-hardened tool, while others are shipped products — and they differ in surface (terminal and CI, desktop with parallel and scheduled tasks and mobile control). Do not read shared shape as interchangeability, and do not read it as evidence that any one of them works well; none of the source facts reports comparative performance.
